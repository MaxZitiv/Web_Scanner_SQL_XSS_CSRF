# Ревизия DashboardWindow

## Что обнаружено

До консолидации существовали четыре файла общим объёмом 3271 строка:

| Файл | Строк | Результат ревизии |
| --- | ---: | --- |
| `views/dashboard_window_updated.py` | 1196 | Наиболее полная версия: профиль, статистика, пять форматов отчётов, ZAP, очистка истории. Выбрана основой. |
| `views/dashboard_window_fixed.py` | 1041 | 15 из 23 методов полностью совпадали с `updated` по AST. Новых имён методов не было. |
| `views/dashboard_window_optimized.py` | 994 | 10 из 18 методов полностью совпадали с `updated` по AST. Новых имён методов не было; часть функций отсутствовала. |
| `views/dashboard_window_wrapper.py` | 40 | Обёртка над `optimized`, дополнительно вызывавшая `QWidget.__init__` перед конструктором панели. |

Дублирование затрагивало построение интерфейса, стили, обработчики событий,
настройки и управление задачами. При этом `MainWindow.go_to_dashboard()` и
`MainWindow.show_dashboard()` создавали **разные реализации**. Поэтому результат
зависел от маршрута навигации, а исправления приходилось переносить между копиями.

Полезные различия старых версий не отброшены: подтверждения безопасности,
остановки и выхода теперь явно выбирают **«Нет» по умолчанию**.

## Одна реализация и границы модулей

Все четыре прежних файла удалены. Единственный импорт панели:

```python
from views.dashboard_window import DashboardWindow
```

| Модуль | Ответственность |
| --- | --- |
| `views/dashboard_window.py` | Единственный класс окна: связывание сигналов, владение задачей, навигация и дочерние окна. |
| `views/dashboard/widgets.py` | Построение одного дерева виджетов, стили, типизированный набор ссылок `DashboardWidgets`. |
| `views/dashboard/scan_state.py` | Подготовка URL/типов сканирования и единые правила доступности элементов управления. |
| `views/dashboard/presentation.py` | Нормализация статистики, итоговые сообщения, безопасное отображение лога и строк уязвимостей. |
| `views/dashboard/reports.py` | Сбор полных строк таблицы, выбор JSON/CSV/PDF/HTML/TXT и делегирование сохранения `ExportUtils`. |

Это композиция, а не новая иерархия mixin-классов. Имеющиеся `StatisticsWidget`,
`StatisticsWindow`, ZAP viewer, `ScanController`, `ExportUtils` и функции разбора
места уязвимости используются повторно. Несвязанные старые компоненты в
`views/mixins`, `views/managers` и `views/tabs` не подключались автоматически
и не удалялись в рамках этой ревизии.

Класс окна уменьшен с 1196 до примерно 420 строк; вместе со вспомогательными
модулями реализация занимает около 800 строк вместо четырёх файлов на 3271 строку.
Это измеренное сокращение дублирования, **не утверждение об ускорении сканера**.
Графический лог ограничен 2000 блоками документа; файловые логи и история БД
этим ограничением не затрагиваются. Payload и URL в логе отображаются как текст,
а не HTML.

## Жизненный цикл

- `show_dashboard()` делегирует `go_to_dashboard()`. Оба пути используют один
  класс, одну модель пользователя и одинаковые проверки.
- Поддерживается любой `QWidget` в качестве Qt-родителя. Выход передаётся
  сигналом `logout_requested`, а не поиском `MainWindow` через `parent()`:
  после добавления в стек родителем становится `QStackedWidget`.
- На одно сканирование приходится одна отслеживаемая задача, без вложенного
  фонового запуска и создания незапущенного event loop. Повторный запуск
  блокируется уже после первого нажатия, до первого шага корутины.
- Состояния `IDLE`, `RUNNING`, `PAUSED`, `STOPPING` определяют доступность URL,
  флажков и кнопок. Остановка не переводит панель в `IDLE` преждевременно.
- При обычной остановке, выходе или закрытии выполняется кооперативная остановка
  контроллера с ожиданием возврата из цикла «сканирование → сохранение».
  Текущие сетевые запросы могут завершаться не мгновенно. Задача активного скана
  не отменяется ради немедленного удаления Qt-окна.
- Закрытие `MainWindow` и переход к другому экрану также ждут этого завершения.
  На одну операцию выхода приходится одно подтверждение; повторное событие
  закрытия не открывает второй диалог. После завершения закрываются дочерние
  окна и останавливается таймер ZAP viewer.
- Отдельно обработана отмена задачи до её первого шага. Завершение старой задачи
  не должно восстанавливать управление вместо новой задачи.

SQL/XSS/CSRF, история с изоляцией пользователей, профиль, прогресс, статистика,
место уязвимости и полные подсказки сохранены. Глубина 10 и параллельность 5
по-прежнему задаются в `ScanController`, а не копируются между окнами.
В экспортируемых данных ключ `Параметр` сохранён для совместимости, хотя
заголовок соответствующего столбца интерфейса — `Место в коде`.
Отмена сохранения файла не показывается повторно как ошибка экспорта.

## Регрессионные проверки

```sh
python -m ruff check .
python -m pyright
python -m pytest -q
```

- `test_dashboard_structure.py`: одно окно и отсутствие импортов удалённых
  вариантов; второй маршрут навигации делегирует первому.
- `test_dashboard_helpers.py`: параметры, состояния, статистика и форматирование
  без запуска Qt.
- `test_dashboard_ui.py`: реальные Qt-виджеты/сигналы с управляемым фальшивым
  сканированием; запуск, ошибки, отмена, пауза/остановка, выход/закрытие,
  навигация, отчёты и согласованность очистки истории.
- Существующие `test_scan_history_database.py` и `test_scan_history_ui.py`
  продолжают проверять транзакционность удаления, изоляцию пользователей
  и синхронизацию открытых окон.

Сетевое сканирование в тестах не выполняется, базы временные. GUI-тесты требуют
системных библиотек Qt и работают в `offscreen`. Полная CI-проверка использует
Python 3.14, предварительно проверяет импорт Qt, выполняет весь набор тестов
и проверяет, что обе БД рабочей копии остались неизменными. Сводка тестов и ошибки
публикуются в аннотациях Actions; временные журналы/JUnit находятся в `.cache`.
