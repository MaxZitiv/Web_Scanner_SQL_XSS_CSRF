# Каталоги пейлоадов

Определения пейлоадов находятся только в пакете `payloads/`. Это обычные
Python-модули с данными, без загрузки GUI, сканеров, БД или сетевых клиентов.
Отдельный пакет не создаёт обратную зависимость
`utils.vulnerability_scanner` → `scanner.__init__`: инициализация `scanner`
сама подключает проверки и утилиты приложения.

| Файл | Наборы | Число элементов |
| --- | --- | ---: |
| `payloads/sql.py` | `SAFE_SQL_PAYLOADS`, `SQLI_PAYLOADS`, `ADVANCED_SQL_PAYLOADS` | 14 / 6 / 6 |
| `payloads/xss.py` | `SAFE_XSS_PAYLOADS`, `XSS_PAYLOADS`, `ADVANCED_XSS_PAYLOADS` | 10 / 3 / 7 |
| `payloads/csrf.py` | `SAFE_CSRF_PAYLOADS` | 4 |
| `payloads/ssrf.py` | `SSRF_PAYLOADS` | 10 |
| `payloads/xxe.py` | `XXE_PAYLOADS` | 2 |
| `payloads/rce.py` | `RCE_PAYLOADS` | 8 |

Перенесены существующие **10 наборов, 70 элементов**, без добавления новых
пейлоадов. Основные, простые и расширенные наборы намеренно не объединяются:
у них разный состав и порядок, а проверки используют срезы и первый элемент.
Названия `SAFE_*` сохранены из прежнего API и не являются гарантией безвредности.
Используйте проверки только для разрешённого тестирования.

## Импорт и настройка

Импортируйте только нужные наборы из соответствующего модуля:

```python
from payloads.sql import SAFE_SQL_PAYLOADS
from payloads.xss import SAFE_XSS_PAYLOADS

# Для индивидуального изменения нужен свой список, а не изменение общего.
custom_sql_payloads = SAFE_SQL_PAYLOADS.copy()
```

Константы аннотированы как `Final[list[str]]`: тип списка оставлен совместимым
с прежними публичными наборами. `Final` запрещает переопределение имени при
проверке типов, но не делает содержимое списка неизменяемым.
`AdvancedScanner` копирует шаблоны в свои прежние атрибуты, поэтому экземпляры
по-прежнему можно настраивать независимо.

`Scanner`, `ScanWorker` и простой сканер импортируют данные из `payloads/`.
Старые имена в `scanner.scanner_fixed`, `scanner._scanner_config` и
`utils.vulnerability_scanner` доступны как реэкспорты, без повторных определений.
Пакет включён в поиск пакетов setuptools и не требует отдельных файлов данных
или изменений путей при запуске приложения.

## Что осталось без изменений

- Строки, порядок, конечные пробелы SQL и внутренние отступы/переносы XML.
- Срезы `[:3]`, `[:5]`, общий лимит и выбор `[0]` для форм.
- Алгоритмы отправки запросов, обнаружения уязвимостей и проверки URL.
- Регулярные выражения обнаружения, названия CSRF-полей и описание
  «отсутствует CSRF-токен»: это правила/метаданные, а не отправляемые пейлоады.

## Проверки

На поддерживаемом Python 3.14:

```sh
python -m pytest -q tests/test_payloads.py tests/test_payload_consumers.py
```

Тесты проверяют контрольные суммы всех исходных наборов, независимость импорта,
включение пакета в поставку, реэкспорты, копирование списков, порядок и лимиты
в реальных методах сканеров. HTTP заменён заглушками; пейлоады не отправляются.
При намеренном изменении каталога нужно также обновить ожидаемый размер и
контрольную сумму соответствующего набора в `tests/test_payloads.py`.
