# Улучшения безопасности и надёжности

Ревизия сфокусирована на трёх границах доверия: ответы сканируемого сайта,
данные в отчётах и ключ шифрования. Это не заявление о завершённом аудите
безопасности всего приложения.

## 1. Сеть основного сканера

`utils/http_safety.py` используется основным `ScanWorker` (GUI/CLI) и
`NetworkManager`. Создаваемые ими сессии используют проверку DNS в resolver
самого TCP-коннектора, а не отдельную проверку до повторного разрешения имени.

- Отклоняются loopback, private, link-local, multicast, CGNAT и другие
  непубличные IP, в том числе смешанные публичные/приватные ответы DNS.
  Проверяются также некоторые переходные механизмы IPv6.
- Адреса форм и каждый redirect должны оставаться в пределах исходного
  **scheme + hostname + port**. Разрешён HTTP:80 → HTTPS:443 того же хоста,
  но не обратный переход. Userinfo, управляющие символы и неоднозначный host
  запрещены; `Host` формируется из проверенного URL.
- Автоматическое следование redirects отключено. Для GET/HEAD разрешено
  максимум 5 проверенных переходов с общим бюджетом времени на цепочку.
  POST не повторяется автоматически при ошибке или перенаправлении.
- Сохраняется проверка TLS; отключающие её параметры, переопределение SNI и
  явный proxy не принимаются. Собственные сессии не читают proxy из окружения.
- Ответ ограничен **2 МиБ** как в переданном, так и в распакованном виде.
  Чтение потоковое; gzip/deflate распаковываются с ограничением выходного буфера.
  Бинарные файлы не скачиваются целиком, неизвестные кодировки отклоняются.
- Общий кэш HTTP-ответов удалён из обоих клиентов: ответы с cookies/авторизацией
  и результаты POST не смешиваются между сессиями и не подменяют свежие проверки.
- Исправлена передача пользовательских заголовков: `headers` больше не
  передаётся дважды. Проверка входного URL отделяет hostname от port.

**Изменение поведения:** переход на `www`, поддомен, другой порт или другой
сайт требует отдельного явного запуска. Если ответ превышает лимит или сайт
доступен только через proxy/приватный DNS, основной сканер его пропускает с
предупреждением. Пропуск не означает отсутствие уязвимостей. Лимиты объявлены
в `utils/http_safety.py`; их повышение увеличивает потребление ресурсов.

Проверка DNS гарантируется собственными сессиями `create_session()`, а не
любым произвольным `aiohttp.ClientSession`, переданным сторонним кодом.

## 2. Отчёты и отображение найденных данных

- Все динамические значения в общем и одиночном HTML-отчёте экранируются.
  Пейлоады показываются текстом, а не исполняемой разметкой.
- В отчёты добавлены CSP (`default-src 'none'`, запрет скриптов, форм и base)
  и запрет передачи referrer. Внешние ресурсы отчёту не нужны.
- CSV защищён от formula injection, включая динамические заголовки, начальные
  пробелы/управляющие символы и Unicode-варианты вводных символов. К таким
  строкам добавляется апостроф; CSV-кавычек для этой защиты недостаточно.
- CSV включает объединение столбцов всех строк. Разные типы уязвимостей больше
  не приводят к частичному файлу из-за несовпадения полей.
- Одинаково обрабатываются JSON-строки `result` из SQLite и уже разобранные
  списки. Некорректные элементы не обрушивают весь отчёт.
- Исправлено распознавание высокой серьёзности «Высокая» из панели.
- Динамические QLabel в просмотрщике ZAP используют PlainText.

Общие правила находятся в `utils/report_safety.py` и используются также CSV-
экспортом ZAP. JSON сохраняет исходные значения: для машинного анализа точных
пейлоадов используйте JSON, а не защищённое представление формул в CSV.

## 3. Ключ шифрования и ошибка сохранения

`utils/key_storage.py` сохраняет прежний формат: 32 случайных байта в `.db_key`.
Формат существующих зашифрованных записей не меняется; поддерживается также
обычный токен Fernet без дополнительной обёртки base64.

- Нет ключа, производного от имени пользователя/компьютера/CWD, при ошибках I/O.
  Ошибка хранения приводит к отказу, а не к продолжению с предсказуемым ключом.
- Существующий повреждённый ключ не перезаписывается и не обрезается.
- Новый ключ публикуется атомарно без перезаписи: параллельные процессы читают
  один полностью записанный файл. Временные ключи также исключены из Git.
- Отклоняются ссылки, устройства и подмена файла при открытии. На POSIX
  проверяются владелец и отсутствие доступа группы/остальных пользователей.
- Расшифровка при отсутствии ключа не создаёт новый ключ. Обычные строки вроде
  `N/A` больше не ошибочно считаются шифротекстом.
- Если сохранение скана не удалось, контроллер возвращает `saved=False`.
  Панель отменяет отложенный выход/закрытие, оставляет результаты в таблице и
  сообщает об ошибке: их можно экспортировать до устранения проблемы.

**Перед обновлением сделайте резервные копии БД и исходного `.db_key`.**
Не удаляйте ключ и не создавайте новый для расшифровки старых записей.
На POSIX ключ должен принадлежать пользователю приложения и иметь права `0600`
или строже. На Windows дополнительно ограничьте NTFS ACL каталога/файла.

Для установки в каталог только для чтения можно задать абсолютный путь
`WEB_SCANNER_KEY_FILE` к исходному ключу в личном защищённом каталоге вне
репозитория. Автоматического переноса/перешифрования нет. Если ранняя версия
работала с системным fallback-ключом, сначала экспортируйте данные в прежнем
окружении: небезопасный fallback намеренно не восстанавливается автоматически.

## Проверки и следующие шаги

Добавлены регрессионные проверки HTML/CSV, сохранности старых ciphertext,
повреждённых/недоступных ключей, конкурентного создания, DNS/redirect/TLS,
лимита распаковки, таймаута, изоляции ответов и поведения GUI при отказе записи.
Тесты используют временные БД/ключи, подменённые HTTP/DNS и не сканируют сайты.
CI проверяет Ruff, строгий Pyright, Bandit для новых защитных модулей и весь
pytest-набор на Python 3.14 с Qt; проверяется неизменность всех отслеживаемых БД.

Следующие отдельные этапы, **не выполненные этим изменением**:

1. Перевести старые `RequestManager`, `Scanner`, `AdvancedScanner` и синхронные
   `utils.vulnerability_scanner` на тот же сетевой транспорт; до этого нельзя
   приписывать им гарантии основного `ScanWorker`.
2. Ввести явные политики разрешённых внутренних сетей/поддоменов, общий бюджет
   сканирования (URL, время, память), контроль нагрузки и корректный учёт покрытия.
3. Унифицировать аутентификацию, блокировку перебора и проверки владельца во всех
   старых API отчётов/редактирования; пересмотреть хранение чувствительных логов.
4. Закрепить зависимости lock-файлом, автоматизировать проверку CVE и расширить
   тестирование качества детекторов: отсутствие находок не доказывает безопасность.
